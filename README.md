# dubli: поиск дубликатов файлов

Консольная утилита на C, которая находит файлы с одинаковым содержимым: копии фотографий после нескольких выгрузок с телефона, дважды скачанные дистрибутивы, папки «backup (2)». Показывает, сколько места можно освободить, и умеет удалить лишнее или заменить копии жёсткими ссылками.

## Возможности

**Поиск**
- Четыре ступени отбора: размер → хэш первых 4 КиБ → хэш всего файла → побайтовое сравнение. Большинство файлов отсеиваются без чтения, а до полного чтения доходят только реальные кандидаты.
- Побайтовая проверка в конце исключает ложные совпадения хэша. Ключ `--fast` её отключает.
- Жёсткие ссылки и один и тот же файл, указанный дважды, не считаются дубликатами: их удаление не освобождает места.
- Символьные ссылки, устройства и сокеты внутри дерева пропускаются, поэтому обход не уходит за пределы папки и не зацикливается.

**Отбор файлов**
- `-m 10M` — минимальный размер, `-e` — учитывать пустые файлы.
- `-x 'node_modules' -x '*.tmp' -x '*/cache/*'` — исключения по маске имени или пути.
- Скрытые файлы и папки пропускаются, пока не указан `-a`.

**Что оставить**
- `-k first` (по умолчанию) — файл из пути, указанного первым: `dubli originals/ backup/` сохранит оригиналы.
- `-k oldest`, `-k newest` — по времени изменения, `-k shortest` — самый короткий путь.

**Действия**
- `-d` удаляет копии, `-l` заменяет их жёсткими ссылками на оставленный файл (имя остаётся, место освобождается).
- `-n` показывает план без изменений.
- Перед каждым действием файл проверяется заново: если после сравнения изменились размер, время или inode, он не трогается.
- Ссылка создаётся под временным именем и атомарно переименовывается поверх копии, так что путь не пропадает ни на миг.

**Вывод**
- Текст для человека, `-f json` и `-f csv` для скриптов и таблиц. В режимах json/csv журнал действий уходит в stderr и не портит данные.
- Группы отсортированы по объёму, который они занимают впустую.

## Стек

C11, POSIX (`opendir`, `lstat`, `link`, `rename`, `fnmatch`, `getopt_long`), Make. Без внешних библиотек. Собирается на Linux и macOS (GCC и Clang).

## Запуск

```bash
git clone https://github.com/whysafe/dubli.git
cd dubli
make
./dubli ~/Pictures
```

Установка в `/usr/local/bin`:

```bash
sudo make install
```

Примеры:

```bash
# только итог по домашней папке, файлы от 1 МиБ, без кэшей
dubli -s -m 1M -x '.cache' -x node_modules ~

# посмотреть, что будет удалено, затем удалить
dubli -d -n ~/Downloads ~/Downloads/old
dubli -d ~/Downloads ~/Downloads/old

# заменить копии в медиатеке ссылками, оставив самые старые файлы
dubli -l -k oldest /srv/media

# отчёт для таблицы
dubli -f csv ~/Documents > duplicates.csv
```

Коды выхода: `0` — успешно, `1` — ни один путь не открылся или действие завершилось с ошибкой, `2` — неверные аргументы.

## Как устроено

```
src/
  scan.c     обход дерева, фильтры, удаление повторов inode
  hash.c     FNV-1a 64, хэш начала и всего файла, побайтовое сравнение
  group.c    ступени отбора и выбор оставляемого файла
  report.c   text, json, csv и итоговая сводка
  actions.c  удаление и замена жёсткими ссылками с повторной проверкой
  main.c     разбор аргументов
```

- Все найденные файлы лежат в одном массиве. Он сортируется по размеру, и каждая ступень сортирует только свой отрезок массива — по хэшу начала, затем по полному хэшу. Одинаковые значения оказываются рядом, поэтому группы выделяются одним проходом без хэш-таблиц.
- Группа хранит индексы в этом массиве. Она создаётся после того, как её отрезок отсортирован в последний раз, поэтому индексы остаются верными.
- Файлы не больше 4 КиБ целиком читаются уже на второй ступени, и полный хэш для них не считается повторно.
- Повторы inode убираются до поиска: сортировка по `(st_dev, st_ino)` и проход с оставлением первого пути.

## Тесты

```bash
make test
```

- `tests/test_unit.c` — модульные тесты: эталонные значения FNV-1a, разбор и форматирование размеров, русские окончания, маски исключений, порядок выбора оставляемого файла, экранирование JSON.
- `tests/cli.sh` — интеграционные тесты на живой файловой системе: дерево с копиями, жёсткой ссылкой, скрытой папкой, пустыми файлами и файлами с общим началом; проверяются вывод, JSON и CSV, коды выхода, пробный запуск, удаление и замена ссылками (сверка inode).

В GitHub Actions тесты идут на Ubuntu и macOS с `-Werror`, а отдельная задача собирает проект с AddressSanitizer и UndefinedBehaviorSanitizer.
